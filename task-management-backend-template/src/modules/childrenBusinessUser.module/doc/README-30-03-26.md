## 🎯 Overview

**Purpose**: Enables business users (parents/teachers) to manage child accounts and family team members. Handles parent-child relationships, permissions, and task assignment capabilities.

**Business Value**: Allows parents/teachers to create and manage multiple child accounts under one subscription, assign tasks, and monitor progress. Essential for family task management and parental control features.

**Users**: 
- **Business Users** (Parents/Teachers) - Create and manage child accounts
- **Child Users** - Managed accounts with task permissions
- **Secondary Users** - Trusted children with task creation privileges

## ✨ Key Features

- ✅ **Create Child Accounts** - Business users can add children to their family
- ✅ **Invitation Flow** - Optional flow where children set their own passwords (for teens 13+)
- ✅ **Profile Management** - Update child information (name, email, support mode, etc.)
- ✅ **Remove/Reactivate** - Soft delete and restore child accounts
- ✅ **Secondary User System** - Designate one child as "Task Manager" with special privileges
- ✅ **Team Members Dashboard** - View all children with task progress statistics
- ✅ **Family Members List** - Children can see their siblings
- ✅ **Permission Management** - Control which children can create tasks
- ✅ **Email Credentials** - Automatic email sending on account creation
- ✅ **Redis Caching** - Optimized queries for team members list and statistics

## 🏗️ Architecture Design

### Design Principles

1. **Parent-Child Relationship**: Direct relationship via `ChildrenBusinessUser` model (not through groups)
2. **Soft Delete**: Accounts are never hard deleted, only marked as `removed`
3. **Subscription Enforcement**: Business subscription required to add children (commented out for flexibility)
4. **Cache-First**: All read operations check Redis cache before database
5. **Async Email**: Email sending never blocks account creation
6. **Dual Flow Support**: Both parent-creates-password and child-sets-password flows

### Tech Stack
- **Database**: MongoDB (Mongoose)
- **Cache**: Redis (cache-aside pattern)
- **Email**: Nodemailer (SendGrid/AWS SES)
- **Validation**: Zod
- **Auth**: JWT (from auth module)

## 🔄 Data Flow

### Create Child Account Flow

```
Parent (Business User)
    ↓
POST /children-business-users/children
    ↓
Controller: createChild()
    ↓
Service: createChildAccount()
    ├─→ Verify business user exists
    ├─→ Check email uniqueness
    ├─→ Hash password (bcrypt 12 rounds)
    ├─→ Create UserProfile (supportMode, location, dob, gender)
    ├─→ Create User account (role: child)
    ├─→ Create relationship record
    ├─→ Send credentials email (async)
    ├─→ Invalidate Redis cache
    └─→ Return { childUser, relationship }
    ↓
Response: 201 Created
```

**Figma Reference**: `create-child-flow.png`

**Middleware**: `auth(TRole.business)`, `rateLimiter('strict')`, `validateRequest`

**Redis Cache Keys Invalidated**:
- `children:business:{userId}:children`
- `children:business:{userId}:count`

---

### Invitation Flow (Optional - Learning)

```
Parent (Business User)
    ↓
POST /children-business-users/children/invite
    ↓
Controller: inviteChild()
    ↓
Service: inviteChildAccount()
    ├─→ Verify business user exists
    ├─→ Check email uniqueness
    ├─→ Generate activation token (64 chars)
    ├─→ Store token in Redis (24h TTL)
    ├─→ Send invitation email with deep link (async)
    └─→ Return { message, expiresAt }
    ↓
Child receives email
    ↓
Clicks activation link (deep link)
    ↓
POST /activate-account
    ↓
Controller: activateAccount()
    ↓
Service: activateAccount()
    ├─→ Verify token from Redis
    ├─→ Check email uniqueness
    ├─→ Hash password (bcrypt 12 rounds)
    ├─→ Create UserProfile
    ├─→ Create User account
    ├─→ Create relationship
    ├─→ Generate JWT tokens (auto-login)
    ├─→ Invalidate token
    └─→ Return { user, tokens }
    ↓
Child logged in automatically
```

**Figma Reference**: `create-child-flow.png` (Invitation variant)

**Middleware**: `auth(TRole.business)` for invite, `none` for activation

**Redis Cache Keys**:
- `activation:token:{token}` (TTL: 24 hours)

## 🔧 Services

### createChildAccount()

**Purpose**: Create a child account and add to family

**Figma Reference**: `create-child-flow.png`

**Flow**:
1. Verify business user exists and get name
2. Check if email already exists
3. Hash password (bcrypt, 12 rounds)
4. Create UserProfile (supportMode, location, dob, gender)
5. Create User account (role: child, accountCreatorId = businessUserId)
6. Create parent-child relationship record
7. Send credentials email (async, non-blocking)
8. Invalidate Redis cache
9. Return { childUser, relationship, message }

**Redis Cache Keys Invalidated**:
- `children:business:{userId}:children` (TTL: 10 min)
- `children:business:{userId}:count` (TTL: 10 min)

**Endpoint**: `POST /children-business-users/children`

**Middleware**: `auth(TRole.business)`, `rateLimiter('strict')`, `validateRequest`

## 🗄️ Redis Caching

| Key Pattern | TTL | Use Case | Invalidation |
|-------------|-----|----------|--------------|
| `children:business:{userId}:children` | 10 min | Cache children list | On create/update/remove |
| `children:business:{userId}:count` | 10 min | Cache children count | On create/update/remove |
| `children:team-list:{userId}:page-{page}-limit-{limit}` | 3 min | Cache team members list with pagination | On create/update/remove |
| `children:team-statistics:{userId}` | 5 min | Cache team statistics | On create/update/remove |
| `activation:token:{token}` | 24 hours | Store invitation tokens | On activation or expiration |

### Cache Strategy

**Pattern**: Cache-aside (lazy loading)

**On Read**:
1. Check Redis cache
2. If hit → return cached data
3. If miss → read from database
4. Cache result
5. Return data

**On Write**:
1. Perform database operation
2. Invalidate related cache keys
3. Return response

**Cache Invalidation**:
```typescript
private async invalidateCache(
  businessUserId: string,
  childUserId?: string,
): Promise<void> {
  const keysToDelete = [
    this.getCacheKey('children', businessUserId),
    this.getCacheKey('count', businessUserId),
  ];
  
  if (childUserId) {
    keysToDelete.push(this.getCacheKey('parent', undefined, childUserId));
  }
  
  await redisClient.del(keysToDelete);
}
```
