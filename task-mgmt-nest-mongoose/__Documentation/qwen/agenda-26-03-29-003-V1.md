## 🔧 EXPRESS → NESTJS TRANSITION NOTES

### **Pattern Changes**

| Express Pattern | NestJS Pattern |
|-----------------|----------------|
| `router.post('/stripe/webhook')` | `@Controller('stripe-webhook')` + `@Post()` |
| `stripe.paymentIntents.create()` | StripeService with DI |
| `SSLCommerzPayment.validate()` | SSLService with DI |
| `crypto.createHmac()` | Node.js crypto (same) |
| `GenericController` | Extend `GenericController` |
| `sendResponse(res, {...})` | Return value + interceptor |
| `catchAsync()` | Built-in async/await |

### **Architecture Patterns**

1. **Strategy Pattern** (Preserved)
   - `PurchaseStrategy` abstract class
   - Different strategies for different purchase types

2. **Gateway Pattern** (Preserved)
   - `PaymentGateway` interface
   - Stripe, RevenueCat, SSLCommerz implementations

3. **Webhook Handlers** (Modular)
   - Separate handler per event type
   - Idempotency checks
   - Signature verification

## 🚨 RISKS & MITIGATION

| Risk | Impact | Mitigation |
|------|--------|------------|
| Webhook signature verification | High | Use official SDKs, test thoroughly |
| Idempotency bugs (duplicate charges) | Critical | Redis-based locking, database unique constraints |
| Transaction safety | High | MongoDB transactions, rollback on error |
| Test data | Medium | Use Stripe test mode, RevenueCat sandbox |
| Secret management | High | ConfigService + .env, never commit secrets |
